# M4 benchmark tree

Executable evidence for the M4 comparison defined in
[`docs/benchmarks/M4/`](../../docs/benchmarks/M4/). M1 evidence in
`validation/` is historical and is not modified from here.

**Status:** W1 (`jsontool`) implemented and correctness-green in five
languages. No timing or scoring has been collected.

## Layout

```text
benchmarks/m4/
  README.md                 this file
  fixtures/w1_json/         deterministic input bytes + generator
  expected/w1_json/         declarative golden cases (stdout/stderr/exit)
  apps/{mink,python,rust,go,csharp}/w1_json/
  harness/
    common.py               paths, language registry, case resolution
    build.py                builds each implementation into .build/
    run.py                  runs one case, captures bytes, emits a record
    validate.py             full correctness gate, PASS/FAIL matrix
    pe_imports.py           read-only PE import inspection
  results/raw/              generated JSONL (git-ignored)
  .build/                   generated artifacts (git-ignored)
```

## Commands

```text
python benchmarks/m4/fixtures/w1_json/make_fixtures.py   # regenerate fixtures
python benchmarks/m4/harness/build.py --workload w1_json # build all five
python benchmarks/m4/harness/validate.py --workload w1_json
python benchmarks/m4/harness/run.py --workload w1_json --language go \
       --case sum_records --json
python benchmarks/m4/harness/pe_imports.py <exe>
```

`validate.py` exits 0 only when every scored and supporting case passes in
every requested language, and writes
`results/raw/w1_json/correctness-w1_json.jsonl`.

## Rules

- Fixtures are deterministic and committed; no random data, no network.
- Expected bytes are authored from the contract, never generated by running
  an implementation.
- Build outputs and results stay out of git.
- Rust builds use `--offline`; the harness never downloads a dependency.
- No timing is recorded here until all five implementations of a workload
  pass the correctness gate.
