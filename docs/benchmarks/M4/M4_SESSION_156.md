## 1. Contract

Source of truth: `validation/h_manifest/main.mink`, `python_ref.py`,
`record.md`.

```text
manifest <config.json>
```

- Config: JSON object with `root` (string), `out` (string) and `extensions`
  (array of strings).
- The tool walks `root` recursively, selects files whose extension matches any
  listed extension **case-insensitively**, reads each file, computes SHA-256,
  and writes `path,size,sha256,ext` CSV with LF records and RFC-4180 quoting.
  `sha256` is the first 16 hex characters, matching M1. `path` is relative to
  `root` with `/` separators and is sorted in byte order so traversal order
  cannot affect the report.
- stdout (CRLF): `files=<count>`, `bytes=<total>`, `first=<first path>`.
- Exit codes: 0 ok; 1 usage (argument count, option-looking argument);
  2 config missing/not a regular file; 3 invalid JSON, not an object, missing
  key or wrong type; 4 root missing or report unwritable; 5 no file matched.
- Error messages are `manifest: <label>` on stderr with no stdout.
- No timestamps, permissions or absolute paths appear in the report, so the
  output is deterministic and machine-independent.

## 2. Fixtures

Generated by `benchmarks/m4/fixtures/w5_manifest/make_fixtures.py`
(deterministic, re-runnable):

- `tree_100` — exactly 100 files. Ten special files: nested directories with
  a space in one name, an empty file, a 256-byte binary file (`skip.bin`), a
  CSV with a comma in its **name** (`data/comma,name.txt`), UTF-8 **content**
  in an ASCII-named file, an extension-less file, and mixed `.txt`/`.csv`
  bulk records. **97 files match** `.txt`/`.csv`; 3 do not.
- `tree_400` — the same specials plus 390 bulk files; **397 match**.
- Path names are ASCII by design. Non-ASCII **names** are the separate probe
  in §4, because MINK's filesystem layer is ANSI.
- Expected stdout: `files=97 bytes=918 first=bulk/g000.txt` (baseline) and
  `files=397 bytes=3618 first=bulk/g000.txt` (scale).

Each case runs in its own work directory (`results/work/w5_manifest/<case>/
<language>/`) containing `tree/`, `out/` and a `config.json` with **relative**
paths, so no fixture path leaks into the report or the transcript.

## 4. Unicode-path probe (capability evidence, not scored)

`benchmarks/m4/harness/probe_unicode.py` creates `naïve café.txt`,
`日本語.txt`, `nested/café notes.txt` and `plain.txt`, then runs each
implementation once. Evidence: `results/raw/w5_manifest/unicode-probe.json`.

| Language | Exit | stdout | Report behaviour |
| --- | --- | --- | --- |
| MINK | 0 | `files=4`, `bytes=97`, `first=???.txt` | `日本語.txt` becomes `???.txt` with `size -1` and the **empty-string** hash `e3b0c442…`; `café` names are emitted as single ANSI bytes (invalid UTF-8) |
| Python | 0 | `files=4`, `bytes=127`, `first=naïve café.txt` | all four names and SHA-256 values correct |
| Rust | 0 | identical to Python | identical |
| Go | 0 | identical to Python | identical |
| C# | 0 | identical to Python | identical |

This is the documented MINK ANSI filesystem limitation in concrete form, not a
benchmark defect and not hidden:

- a name the code page cannot represent is looked up as `?`, so the file is
  reported missing from the hashing step (`size -1`) while still being counted;
- the summary byte total is therefore wrong (97 vs 127);
- non-ASCII names are transcoded rather than UTF-8-encoded.

The probe does not gate W5 and its result is not used to weaken any expected
output. Scored W5 cases stay inside MINK's supported ASCII-path contract.

## 5. Dependencies

| Language | Dependency | Version | Notes |
| --- | --- | --- | --- |
| MINK | `json`, `filesystem`, `hashing`, `csv` | 1.0.4 stdlib | no external package |
| Python | `json`, `os`, `hashlib`, `csv` | 3.11.9 stdlib | stdlib only |
| Rust | `serde_json` | `=1.0.151` | cached, offline build |
| Rust | `sha2` | `=0.10.9` | cached, offline build |
| Go | `encoding/json`, `path/filepath`, `crypto/sha256`, `encoding/csv` | 1.26 stdlib | module has no requirements |
| C# | `System.Text.Json`, `System.Security.Cryptography`; manual CSV writer | .NET 10 in-box | no package reference |

Deviation from the workload plan is recorded rather than hidden: the plan
listed the Rust `csv` crate, but the implementation writes the four-column
report with ~15 lines of RFC-4180 code, so `csv` was not added. C# likewise
uses a manual writer. Python and Go use their stdlib CSV writers; MINK uses
its bundled module. This is an available-API choice, not an effort or fairness
claim.
