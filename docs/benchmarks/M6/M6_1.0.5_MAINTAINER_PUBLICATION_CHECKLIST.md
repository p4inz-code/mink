## Before publishing

**Preserve the tarball first.** `/tmp` is cleared on reboot, and the hash above
is the artifact's identity:

```bash
mkdir -p ~/mink-release
cp /tmp/mink_rc/p4inz-code-mink-1.0.5.tgz ~/mink-release/
sha256sum ~/mink-release/p4inz-code-mink-1.0.5.tgz
# must print cfafc7a810d38e205475eb24a7009f1dfd0fc05feaad4beecfd24c50efc7df6f
```

**Do not rebuild the compiler and copy it over `npm/mink/bin/mink.exe`.** A clean
`cargo build --release` from this source produces a working 1.0.5 compiler of the
same size but a *different* hash (`2568bbbf…` observed), because the Rust build is
not bit-reproducible here. Doing so would silently replace the verified binary.

## Publish — REQUIRES EXPLICIT AUTHORIZATION

Publish the **tarball**, not the directory, so the exact verified artifact is what
lands in the registry:

```bash
npm publish ~/mink-release/p4inz-code-mink-1.0.5.tgz --access public
```

`npm publish ./npm/mink --access public` also works and packs the same verified
binary, but it re-packs, so its hash should be re-checked if it is used.
