## What landed

- `stdlib/tls.mink` (mirrored into the npm bundle): a TLS 1.2/1.3 client and an
  HTTPS client on Windows Schannel —
  `tls_connect(host, port, ca_path, out_err) -> Ptr<Int>`,
  `tls_status`, `tls_err`, `tls_cipher`, `tls_send(h, data) -> Int`,
  `tls_recv(h, maxlen) -> Str`, `tls_close(h) -> Int`,
  `https_client_get_with(host, port, path, ca_path) -> Str` and
  `https_client_get(url, ca_path) -> Str`; documented error codes 1001–1008
  (`E-TLS-LIB` … `E-TLS-PROTO`).
- A general, Windows-only FFI layer in the runtime:
  `rt_sys_load_lib(name) -> Int` (`LoadLibraryA`),
  `rt_sys_get_proc(lib, name) -> Int` (`GetProcAddress`),
  `rt_sys_call(fn, argv, nargs) -> Int` (the Win64 register/stack convention
  for up to 12 word arguments, with an explicitly 16-byte-aligned call site),
  and the unvalidated foreign reads `rt_sys_load64`/`rt_sys_load32` (a foreign
  struct lives outside the MINK arena, so the checked `rt_mem_load` cannot
  reach it). `[code] src/backend/emit/runtime.rs`, `src/backend/ir.rs`,
  `src/runtime/intrinsics.rs`.
- `rt_net_getaddrinfo` upgraded from its V1 pass-through to a real Winsock
  `getaddrinfo` resolution returning an owned dotted-quad `Str` (empty on
  failure, never the borrowed host pointer).
- `rt_exit`/`rt_fail` now terminate through `kernel32!TerminateProcess` after
  the exit-time leak scan (see the platform defect below).
- `tests/tls_lib.rs` — 20 permanent tests; 19 run in CI and each compiles a
  real Windows PE through the `mink build` CLI and executes it. The local
  deterministic server is `tests/tls/server.py`; the committed fixtures are
  generated by `tests/tls/make_certs.py` (a test CA plus leaves with known
  validity, EKUs and SANs).

## Architecture

**Record layer.** The handshake state machine and the record layer are ordinary
MINK source over Schannel (`InitializeSecurityContext`/`AcceptSecurityContext`
rounds, `EncryptMessage`/`DecryptMessage`), not a wrapper around a foreign TLS
stack. The connection context block (1536 bytes) holds the socket, the
credential/context handles, the `StreamSizes` fields, and the ciphertext,
record and plaintext staging buffers; `tls_close` releases it and every handle
with it, so a closed connection passes the exit-time arena check.

**Trust is the client's own decision.** Schannel runs with manual credential
validation (`ISC_REQ_MANUAL_CRED_VALIDATION`) — the mode WinHTTP and curl's
Schannel backend use, and the only one that can express a pinned anchor, since
`SCHANNEL_CRED.hRootStore` alone does *not* make a private CA trusted (measured).
MINK then verifies with crypt32 in three parts, all of which must pass:

1. chain building (`CertGetCertificateChain`) verifies every signature up to a
   root, enforces time validity, and rejects a leaf that is not valid for
   `serverAuth`;
2. the anchor: with a pinned `ca_path` the chain must report nothing except
   `CERT_TRUST_IS_UNTRUSTED_ROOT` (the expected state of a private root) *and*
   the root certificate must be the pinned certificate compared by hash;
   without `ca_path` the chain must be completely clean (system store);
3. the host name must match a `dNSName` SAN (RFC 6125: `*` matches exactly one
   label, at most one wildcard) or an `iPAddress` SAN for an IPv4 literal; the
   subject common name is accepted only when there is no SAN extension at all.

**Name vs. address.** `rt_net_connect` takes an IPv4 literal, so `tls_connect`
resolves the host with `rt_net_getaddrinfo`, connects to the dotted quad, and
keeps the original name for certificate name checking.

**Platform defect (measured, not assumed).** Any `CertGetCertificateChain` call
makes crypt32 deadlock in its `DLL_PROCESS_DETACH` handler: a process that
returns from its entry point after building a chain hangs at exit — triggered
by the chain call alone, so no caller can avoid it. MINK's exit is therefore
`TerminateProcess(GetCurrentProcess(), code)` after its own cleanup (the leak
scan is the last thing the process owes itself), and the failure path
terminates with `100 + error` the same way. Foreign DLL detach handlers are
never run.

## Defects found and fixed (all by native execution)

1. `rt_net_getaddrinfo` was a V1 pass-through, so a real host name could never
   connect — replaced with Winsock resolution (owned result, empty on error).
2. `CryptStringToBinaryA`'s size-query path failed; the PEM decode now uses the
   single-pass call with a capacity buffer.
3. `CRYPT_STRING_BASE64HEADER` is 0, not 1 — the CA decode needed
   `CRYPT_STRING_BASE64_ANY` (6).
4. `SecBuffer`'s field order was inverted (`cbBuffer` is the low dword,
   `BufferType` the high one) — every descriptor was malformed.
5. `DecryptMessage`'s second argument is the message descriptor, not the
   sequence number: passing it in the wrong slot dereferenced NULL.
6. `DecryptMessage` needs the MSDN four-buffer descriptor (`DATA` + three
   `EMPTY`); Schannel then splits the input into header/plaintext/trailer/extra.
   A two-buffer descriptor fails with `SEC_E_INVALID_TOKEN`.
7. `StreamSizes` extraction mis-read the packed struct: `cbTrailer` is the high
   dword of word 0 and `cbMaximumMessage` the low dword of word 1 (TLS 1.3
   reports header 13 / trailer 16 / max message 16384).
8. Schannel shrinks the output buffer's capacity after each call, so the
   capacity must be reset every handshake round.
9. Misaligned 4-byte reads in the packed foreign structures.
10. `https_client_get_with` allocated a 16-byte diagnostic block while
    `tls_connect`'s failure path writes 48 bytes — a heap overwrite fixed.
11. `_recv_all` reserved a 1 MiB window out of the fixed 4 MiB bump heap per
    request, exhausting the arena on the second request; the capacity is now
    sized from the actual response.
12. `tls_send` consumes its `data` argument (the caller must not reuse it);
    the header now states the ownership rule and every path frees it.
13. `tls_close` and the accessors dereferenced a null handle; an empty handle
    now answers every operation with its documented failure value (`-1`, `0`,
    `1007`) and never faults.
14. Invalid-handle contract vs. use-after-close: `tls_close` releases the
    handle (like `rt_free`), so a *reused* pointer is a runtime error by
    design; the test pins the invalid-handle behavior instead.
15. Per-test file roots collided when tests ran in parallel — one root per
    marker now.
16. The test harness drained child pipes only after exit, so the 300 KiB
    transfer wedged; both pipes are now drained concurrently with a hard
    timeout.
17. Pre-existing Linux build break (S63 stdlib wrapper not emitted by the
    frozen ELF backend) restored with the existing stub convention, with no
    Linux behavior change.

  `s62_system_store_public_https`, opt-in public-internet positive path) with
  0 failed; the run is reproducible.
  Positive: pinned-CA handshake (cipher negotiated, clean close), HTTPS GET in
  both forms, SAN match on a later entry, IPv4-literal SAN, binary echo with

  Failure paths: connection refused (`1004`), missing CA (`1003`), malformed CA
  (`1003`), malformed URL (static `""`), invalid/closed handle operations.

  `E-R06` (106). The repeated-connection test exists specifically for this.
- `tests/network_lib.rs`: the resolver test now asserts the real resolution
  contract (the previous test encoded the V1 pass-through stub).
- Broad Windows regression was re-run after the exit-path change (the change
  touches every emitted program): smoke/CLI, compiler, parser/typecheck/HIR/MIR,
  ownership, collections/strings/encoding, filesystem/process, networking,

## Documented limits (not blockers)

- Client only: there is no TLS server, no client certificates, no
  ALPN/HTTP-2, no redirects/cookies/keep-alive (those protocol conveniences
  remain S59's P2 gap). `https_client_get*` performs GET only; POST over TLS
  has no helper yet.
- TLS 1.0/1.1 are not targeted; Schannel's default protocol set applies.
- The FFI layer is deliberately raw (`rt_sys_call` returns `RAX`; the caller
  owns argument and pointer validity). It lives in the stdlib layer, which is
  what makes the trust logic reviewable MINK source rather than assembler.
